# STM32F407 集成检查表

此清单不是接线图。当前不生成 `.ioc`、启动文件、链接脚本或烧录产物，不猜 USART、GPIO、DMA 通道、时钟频率和板载晶振。

## A. 硬件资料到齐前

- [ ] 拍摄最小系统板正反面、丝印版次、MCU 完整型号，取得同版次原理图。
- [ ] 确认供电输入、板载稳压、USB/ST-Link 供电关系及引脚电压容限。
- [ ] 拍摄 BusLinker/串口转接板正反面，确认实际芯片、供电、逻辑电平和 TX/RX/方向控制电路。
- [ ] 排除 CH340 与 MCU 同时驱动总线；核实 HC126 等缓冲器电源与 3.3 V 输入输出兼容性。不要仅凭名字认为旧版转接板安全。
- [ ] 确定舵机独立供电与限流、线径、保险/保护、接地和物理断电急停。LX-16A 产品规格为 6–8.4 V，电源不从 MCU GPIO 或 UART 供给。
- [ ] 机械台架固定、卸除负载/连杆风险、远离手指和夹点；上电力矩状态需确认。

## B. 软件平台实现

在确认硬件后，由 STM32CubeMX/实际工程生成正确板级基础。再实现 Transport：

- verified_ready：只有真实接口、电平、供电和初始化验证后才能为 true，不能改为无条件 true。
- begin_tx：非阻塞启动发送，且与主机回显过滤/半双工方向切换一致。发送数据地址在事务完成或 abort 之前有效。
- poll_tx：忙/完成/错误；完成必须依据 UART TC，而非 DMA TC。物理总线在 TC 事件准确释放；不要等慢速主循环再切换。
- enter_rx：确认已释放发送驱动、接收就绪；不能误删 TC 后已经到达的回应。
- receive：有界、非阻塞读环形缓冲，永不超过调用方容量；溢出要成为可见错误，不能静默当成功。
- clear_rx：清理历史接收数据，但不能保证以后不会有迟到回应。
- abort：停止所有 DMA/UART 对发送缓冲的访问并释放总线，保证返回后不会继续访问数据。真实实现必须另有失败处置。
- ISR 只采集字节/状态，主循环解析。USART 配置使用已核实的 LX-16A 115200、8N1，与 HX-30HM 的 1 Mbps 资料区分。
- 单调毫秒时钟、硬件看门狗、循环执行时间上限、传输错误计数、溢出日志和急停输入尚需实现。

## C. 初次台架调试顺序

1. 先不接舵机，验证 3.3 V 侧信号与收发切换，用逻辑分析仪确认帧及电平。不能在电气兼容性未知时试接。
2. 一次只接一个舵机做只读位置、温度、电压、负载状态测试。默认出厂 ID 可能重复，不假设三个电机可直接并联。
3. 用厂商工具/经审核工具识别并设定唯一 ID，记录关节名称与 ID，检查复电保持；此 v0.1 不实现写 ID/EEPROM。
4. 先明确该机构是不是独立线性传动。测量零点、正负方向、实际角度与 tick 对应、极限及留量；不能复制 `tests/` 中的参数。
5. 如有非线性/耦合、齿轮间隙或机械限制，先替换关节映射模型；`direction * ticks_per_rad` 不能表达所有传动。
6. 人工设定保守速度/步幅/时长与短超时，记录验证证据后再更新 SafetyConfig 的确认标志。
7. 实现并测试丢串口、断线、重复包、堵转、供电异常、热保护、看门狗触发及急停。明确停机时保持位置还是卸载力矩的风险，不能默认卸载后机构不会跌落。
8. 补齐可靠的多电机执行层后才允许小角度空载运动；电机真实到位与故障检测必须依赖反馈。之后再固定台架做单腿。

## 仍未支持或未验证

- ARM 交叉编译、实际 STM32 HAL/CMSIS、Keil/IAR 工程、烧录、板级时钟/中断/DMA
- 任意真实引脚、电气接线、电平转换、BusLinker 版次、独立电源与急停
- 真机通讯、回应时间、丢包率、收发切换/回显、电机温升/负载、末端定位误差
- 真实关节标定、几何、齿轮传动、碰撞/自碰撞、机械间隙
- 同步多电机动作、完整三关节执行器、四腿协调、轨迹生成、步态、遥控链路
- 自动温度/电压监督、超限后的硬件停机、独立硬件看门狗、软件安全认证
- 强化学习训练、仿真模型、状态估计、策略部署、无线鉴权/失联保护

主机测试通过只表明对应软件路径通过了测试，不表示上述未验证项已完成。
